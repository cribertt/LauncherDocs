# Publish your first build

Launcher Forge publishes game builds through an **interactive CLI**.

You do not need to write a deployment command or remember command-line flags. The CLI guides you through the entire process using menus and prompts.

<Warning>
  Publishing a game in the Catalog only makes its game entry visible in the launcher. It does not upload the game files. You must publish at least one build through the CLI before players can install and run the game.
</Warning>

## Before you begin

Confirm that:

- The game exists in the Catalog.
- The game status is **Published**.
- The game has at least one branch.
- CLI access is enabled.
- You have a packaged build that runs correctly.
- Your account has permission to publish builds.
- Your workspace has enough storage available.
- You know which executable starts the game.

<Note>
  Accounts created through Google or GitHub may need to create a Launcher Forge password before signing in to the CLI with email and password.
</Note>

## 1. Open the CLI section

Sign in to the Launcher Forge dashboard.

In the left sidebar, select **CLI**.

Launcher Forge displays the games available for publishing.

Select the game card or use **Open CLI**.

<Info>
  The CLI only retrieves games and permissions available to the authenticated account.
</Info>

## 2. Download the CLI executable

The game-specific CLI page shows:

- Application ID.
- Number of branches.
- Default branch.
- CLI access status.
- Executable version.
- Download size.

Select **Download CLI**.

<Frame caption="Download the Launcher Forge CLI executable">
  <img
    src="/images/screenshots/cli-game-download.png"
    alt="Launcher Forge game CLI page with the Download CLI button highlighted"
  />
</Frame>

The downloaded file is a ready-to-run Windows executable.

You do not need to install it.

You can:

1. Save it on your desktop or another folder.
2. Double-click the executable.
3. Start using the CLI immediately.

<Warning>
  Download the CLI only from the official Launcher Forge dashboard. Do not run copies received from unknown sources.
</Warning>

## 3. Sign in

When no active session exists, the CLI displays:

```text
No active session was found. Sign in to continue.
```

Enter the email address associated with your Launcher Forge developer account.

The CLI then requests your password.

<Frame caption="Sign in with your Launcher Forge email and password">
  <img
    src="/images/screenshots/cli-login.png"
    alt="Launcher Forge CLI requesting the developer account email"
  />
</Frame>

<Note>
  Signing in to the dashboard does not automatically sign in to the CLI. The CLI keeps its own local session.
</Note>

After a successful login, the CLI displays:

- Account email.
- Active plan.
- Account status.
- Storage usage.
- Bandwidth usage.
- Number of games allowed and currently created.

## 4. Select Upload build

The main menu contains the available interactive actions.

Select **Upload build**.

  <img

- List games.

- Version info.
- Logout.

## 5. Select the game

The CLI loads the games available to your account.

Select the game you want to publish.

The game is displayed with its Application ID.

<Frame caption="Select the game that will receive the build">
  <img
    src="/images/screenshots/cli-select-game.png"
    alt="Launcher Forge CLI game selection showing the game name and Application ID"

## 6. Select the branch

After selecting the game, the CLI loads its available branches.

Select the destination branch.

<Frame caption="Select the destination branch">
  <img
    src="/images/screenshots/cli-select-branch.png"
    alt="Launcher Forge CLI branch selection with the main branch available"
  />
</Frame>

Common examples include:

- `main`
- `stable`
- `beta`
- `development`
- An authorized private branch

<Warning>
  Review the selected branch carefully. Publishing a test build to a production branch can expose it to players.
</Warning>

## 7. Enter the version and release type

Enter a new version number.

A semantic version format is recommended:

```text
MAJOR.MINOR.PATCH
```

Examples:

```text
1.0.0
1.1.0
1.1.1
```

Do not reuse a version that already exists for the selected game and branch.

The CLI then asks for the release type.

<Frame caption="Enter the version and select the release type">
  <img
    src="/images/screenshots/cli-release-type.png"
    alt="Launcher Forge CLI version number and STABLE, PATCH, or HOTFIX selection"
  />
</Frame>

<Tabs>
  <Tab title="STABLE">
    Publishes a complete new version of the game.

    All files are uploaded, even when some files already exist.
  </Tab>

  <Tab title="PATCH">
    Publishes a planned update containing smaller changes.

    Launcher Forge compares the manifest and uploads the files required by the new version.
  </Tab>

  <Tab title="HOTFIX">
    Publishes an urgent correction.

    It uses the manifest comparison flow while identifying the release as an urgent fix.
  </Tab>
</Tabs>

## 8. Add release notes and select the build folder

Enter optional release notes or a changelog.

Write a short player-facing description.

Example:

```text
Added controller remapping, improved loading times, and fixed a crash when changing regions.
```

The CLI then requests the path to the packaged game folder.

<Frame caption="Enter release notes and the packaged game folder path">
  <img
    src="/images/screenshots/cli-build-folder.png"
    alt="Launcher Forge CLI release notes and packaged game folder path"
  />
</Frame>

Select the root folder containing the packaged game files.

Example:

```text
MyGameBuild/
├── MyGame.exe
├── MyGame_Data/
├── UnityPlayer.dll
└── Other runtime files
```

Do not select:

- The Unreal Engine or Unity project folder.
- Source code.
- Editor cache.
- Intermediate files.
- Temporary build files.
- Folders containing credentials.

<Warning>
  Do not move, rename, or modify the selected folder while the CLI is scanning or uploading it.
</Warning>

## 9. Confirm the main executable

Launcher Forge scans the selected folder and generates the manifest.

The CLI reports:

- Number of files.
- Number of unique hashes.
- Detected executables.

When one or more executables are found, select the main game executable.

Launcher Forge can mark one option as **Recommended**.

<Frame caption="Confirm the main game executable detected by the CLI">
  <img
    src="/images/screenshots/cli-main-executable.png"
    alt="Launcher Forge CLI showing the generated manifest and recommended main executable"
  />
</Frame>

The selected executable is the file Launcher Forge will use to start the installed game.

<Warning>
  Confirm this value carefully. Selecting the wrong executable can allow the game to install correctly while preventing it from starting.
</Warning>

## 10. Wait for the upload

Before transferring files, the CLI displays the release mode and estimated upload.

For a `STABLE` release, Launcher Forge forces a complete upload of the packaged version.

The CLI then uploads the files and displays the current progress.

<Frame caption="Wait while the game files are uploaded">
  <img
    src="/images/screenshots/cli-upload-progress.png"
    alt="Launcher Forge CLI uploading the files of a STABLE release"
  />
</Frame>

Keep the CLI open and maintain a stable internet connection until the operation finishes.

## 11. Confirm the successful publication

When the process completes, the CLI confirms:

- Build created successfully.
- Version number.
- Release type.
- Destination branch.
- Main executable.
- Successful upload.

<Frame caption="Confirm that the build was published successfully">
  <img
    src="/images/screenshots/cli-upload-success.png"
    alt="Launcher Forge CLI confirming a successfully published STABLE build"
  />
</Frame>

Press **Enter** to return to the main menu.

<Check>
  Your first game build has been published successfully.
</Check>

## What happens after publishing?

After the build is published:

- The version appears in Launcher Forge.
- The release belongs to the selected branch.
- The launcher can use the selected main executable.
- Players can download or update the game when the release is available to them.

Review:

- Version number.
- Branch.
- Release type.
- Release notes.
- Main executable.
- Build status.
- Installation and game startup from the launcher.

## If the upload fails

The CLI displays the cause and should return to a usable menu instead of closing unexpectedly.

Common causes include:

- Invalid or expired session.
- Missing game or branch permission.
- Duplicate version.
- Invalid packaged folder.
- Storage limit reached.
- Network interruption.
- No executable detected.
- Files changed while the upload was running.

Correct the reported cause before retrying.
