# Add your first game

Games are created and managed from the **Catalog** section of the Launcher Forge dashboard.

Each Launcher Forge account currently uses one workspace and one launcher. Every game created in the Catalog belongs to that workspace and can later be connected to the existing launcher.

<Warning>
  Every new game is created as a **Draft** by default.

  A draft is only available inside the developer dashboard. It is not available for launcher distribution until its publishing status is changed to **Published** and the game is linked to the launcher.
</Warning>

<Card title="Required before publishing your first build" icon="shield-halved">
  Before uploading the first production build, configure the validation connection between the launcher and the game.

  This validation allows the launcher to recognize the game runtime and establish a trusted launch connection.

  It is not end-user authentication, ownership validation, or CD key validation. It is specifically the technical connection between the Launcher Forge launcher and the game executable.

  Complete the launcher-game validation before publishing the first build that you intend to distribute.
</Card>

## How the complete process works

Creating a game is only the first part of the distribution flow.

```text
Create the game in the Catalog
        ↓
Publish the game entry
        ↓
Configure launcher-game validation
        ↓
Publish the packaged build
        ↓
Link the game to the launcher
        ↓
Generate and test the launcher
```

The game entry, the packaged build, and the launcher-game validation are separate parts of the system.

## Before you begin

Prepare the following information:

- The public game name.
- A description of the game.
- One or more genres.
- A cover image.
- A packaged game build for a later step.
- The engine integration that will be used for launcher validation.

The game build is not uploaded during game creation. Builds are published later through the Launcher Forge interactive CLI.

## 1. Open the Catalog

Sign in to the Launcher Forge dashboard.

In the left sidebar, locate **MY GAMES** and select **Catalog**.

The Catalog displays:

- Total games.
- Published games.
- Draft games.
- Archived games.
- Search and status filters.

Select **New Game** in the upper-right corner.

## 2. Complete the initial game information

Launcher Forge opens the **Create new game** page.

The interface indicates that the game will initially be created as a draft:

```text
It will be created as a draft
```

Complete the available fields.

### Game name

Enter the public name that will identify the game throughout Launcher Forge.

The name can appear in:

- The Catalog.
- Launcher game cards.
- The launcher library.
- Release information.
- Build selection inside the CLI.

Use a recognizable final name. You can edit it later when necessary.

### Description

Describe the game's universe, mechanics, genre, or main proposition.

The initial description supports up to `500` characters.

Write information intended to describe the game. Avoid internal development notes, credentials, private URLs, or infrastructure details.

### Genres

Select the genres that best represent the game.

Available examples include:

- RPG.
- Action.
- Adventure.
- Strategy.
- Puzzle.
- Simulation.
- Sports.
- Horror.
- Indie.

At least one genre must be selected before creating the game.

### Game cover

The cover image is optional during the initial creation step, but adding one is recommended.

The interface accepts:

- PNG.
- JPG.
- WEBP.
- GIF.

The maximum file size displayed by the form is `10 MB`.

Launcher Forge recommends a `1920 × 1080` image for better visibility inside the launcher.

<Note>
  The game name and at least one genre are required. The cover is optional, but it improves how the game appears in the Catalog and launcher.

## 3. Create the game

After completing the required fields, submit the form.

Launcher Forge creates the game and returns it to the Catalog.

The newly created game appears with the **Draft** status.

<Info>
  Draft means that the game exists inside your workspace but is not ready for launcher distribution.
</Info>

At this point:

- The game exists in the Catalog.
- It does not have a published build yet.
- It is not linked to the launcher yet.
- Launcher-game validation may not be configured yet.
- Players cannot obtain or install it from the launcher.

## 4. Open the game editor

Locate the game card in the Catalog.

Move the pointer over the card and select the pencil icon labeled **Edit game**.

<Frame caption="Open the draft game using the Edit game button">
  <img
    src="/images/screenshots/draft-game-edit.png"
    alt="Draft game card in Launcher Forge with the Edit game button highlighted"
  />
</Frame>

The editor allows you to review and modify the game before making its Catalog entry available for distribution.

## 5. Review the game information

Inside the game editor, review the **Information** tab.

Confirm:

- Game name.
- Short description.
- Full description.
- Selected genres.
- Cover image.
- Banner image, when available.
- Other game metadata.

Save the changes before continuing.

<Note>
  Publishing controls the game's Catalog status. It does not automatically upload a build, connect the game runtime, or link the game to the launcher.
</Note>

## 6. Open the Publishing tab

Inside the game editor, select the **Publishing** tab.

<Frame caption="Open the Publishing tab in the game editor">
  <img
    src="/images/screenshots/game-publishing-tab.png"
    alt="Launcher Forge game editor with the Publishing tab highlighted"
  />
</Frame>

The Publishing tab provides three statuses:

| Status | Behavior |
| --- | --- |
| **Published** | The game entry is available for launcher distribution and can be linked to the launcher. |
| **Draft** | The game remains under preparation inside the developer dashboard. |
| **Archived** | The game is hidden from launcher distribution without being deleted. |

## 7. Publish the game entry

Select **Published**.

Then select **Save changes**.

<Frame caption="Select Published and save the changes">
  <img
    src="/images/screenshots/publish-game-save.png"
    alt="Launcher Forge Publishing tab with Published and Save changes highlighted"
  />
</Frame>

After saving:

- The game stops being a draft.
- The game appears inside the **Published** filter.
- The published counter increases.
- The game becomes available to be linked to the launcher.

<Warning>
  Selecting Published is not enough by itself. You must also select **Save changes** or the new status will not be applied.
</Warning>

<Info>
  Published does not mean that the game immediately appears inside every launcher.

  The game must still be linked to the workspace launcher before it becomes part of its library.
</Info>

## Draft, Published, and Archived

<Tabs>
  <Tab title="Draft">
    Use Draft while the game information is incomplete or while you are preparing:

    - Images.
    - Descriptions.
    - Launcher validation.
    - Branches.
    - Builds.
    - Release information.

    Draft games are not available for launcher distribution.
  </Tab>

  <Tab title="Published">
    Use Published when the game entry is ready to participate in the launcher distribution flow.

    Publishing the entry allows the game to be linked to the launcher, but it does not upload the packaged game files.
  </Tab>

  <Tab title="Archived">
    Use Archived when the game should no longer be available for launcher distribution.

    Archiving does not delete:

    - The game.
    - Its branches.
    - Its builds.
    - Its versions.
    - Its stored files.
  </Tab>
</Tabs>

## Important: publishing the game is not the same as publishing a build

Changing the game status to **Published** only controls its Catalog publishing state.

It does not:

- Upload the game files.
- Create a build manifest.
- Create a version.
- Publish a STABLE, PATCH, or HOTFIX release.
- Select the main executable.
- Configure launcher-game validation.
- Link the game to the launcher.
- Generate the launcher installer.

Game builds are published separately through the Launcher Forge interactive CLI.

## Required: configure launcher-game validation

Before publishing the first build intended for distribution, configure the connection between the launcher and the game runtime.

The purpose of this validation is to allow the launcher to recognize and validate the game it starts.

It is a launcher-to-game connection.

It is not responsible for:

- Registering end users.
- Signing players in.
- Verifying game ownership.
- Redeeming CD keys.
- Managing the player's library.

Those are separate launcher services.

The launcher-game validation flow is responsible for the technical relationship between:

```text
Launcher Forge launcher
        ↓
Game executable
        ↓
Launcher validation integration
        ↓
Trusted launcher-game connection
```

The implementation depends on the game engine:

## Final verification

Before continuing, verify:

- The game appears in the Catalog.
- Its status is **Published**.
- The information is correct.
- At least one genre is selected.
- The cover is displayed correctly.
- The game is available to be linked.
- The correct engine integration has been selected.
- Launcher-game validation is configured.
- The packaged game starts correctly on your computer.
- You are ready to create the first version through the CLI.

<Check>
  Your game entry has been created and published successfully. Complete the launcher-game validation before uploading the first distributable build.
</Check>
