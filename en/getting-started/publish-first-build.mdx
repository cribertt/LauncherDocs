# Publish your first build

Launcher Forge publishes game builds through an **interactive CLI**.

You do not need to create a long deployment command or remember command-line flags. The CLI guides you through the complete process using menus and prompts.

<Warning>
  Publishing the game in the Catalog only makes its entry visible in the launcher. It does not upload the game files. You must publish at least one build through the CLI before players can install and run the game.
</Warning>

## Before you begin

Confirm that:

- The game exists in the Catalog.
- The game status is **Published**.
- The game has at least one branch.
- CLI access is enabled for the game.
- You have a packaged build that runs correctly.
- You know which executable is used to start the game.
- Your workspace has enough storage available.
- Your account has permission to publish builds.

<Note>
  Accounts created through Google or GitHub may need to create a Launcher Forge password before signing in to the CLI with email and password.
</Note>

## 1. Open the CLI section

Sign in to the Launcher Forge dashboard.

In the left sidebar, select **CLI**.

Launcher Forge displays the games available for CLI publishing.

Select the game that you want to publish. You can select the game card or use **Open CLI**.

## 2. Review the game CLI page

The game-specific CLI page shows the information used by the publishing workflow.

Review:

- **Application ID**.
- Number of branches.
- Default branch.
- CLI access status.
- CLI installer version.
- Installer file size.

The Application ID identifies the game internally. The interactive CLI retrieves the available games after login, so you normally select the game from the menu instead of typing this ID manually.

## 3. Download the CLI

Select **Download CLI**.

The download uses your active dashboard session and verifies the password state of your account.

Save the Windows installer to your computer.

<Warning>
  Download the CLI only from the official Launcher Forge dashboard. Do not use executables received from unknown sources.
</Warning>

## 8. Define the release

The CLI requests the release metadata.

### Version

Enter a new version number.

A semantic version format is recommended:

```text
MAJOR.MINOR.PATCH
```

Examples:

```text
1.0.0
1.1.0
1.1.1
```

Do not reuse a version that already exists for the selected game and branch.

### Release type

Select one of the available release types.

<Tabs>
  <Tab title="STABLE">
    Use `STABLE` for a complete release baseline.

    Launcher Forge processes the complete packaged build for the release.
  </Tab>

  <Tab title="PATCH">
    Use `PATCH` for a planned update.

    Launcher Forge compares the new manifest with existing file hashes and uploads the files required by the new version.
  </Tab>

  <Tab title="HOTFIX">
    Use `HOTFIX` for an urgent and focused correction.

    It uses the manifest comparison flow while clearly identifying the release as an urgent fix.
  </Tab>
</Tabs>

### Changelog

Write a short player-facing summary of the changes.

Example:

```text
Added controller remapping, improved loading times, and fixed a crash when changing regions.
```

Do not include passwords, tokens, private URLs, or internal infrastructure information.

## 9. Select the packaged build

Select the local folder containing the compiled and packaged game files.

For example:

```text
MyGameBuild/
├── MyGame.exe
├── Content/
├── Engine/
└── Config/
```

Select the packaged build root, not the Unreal Engine or Unity project directory.

Do not select folders containing:

- Source code.
- Editor caches.
- Intermediate files.
- Temporary build content.
- Credentials or private configuration.

## 10. Analyze and publish

Before uploading, the CLI shows a summary of the selected values.

Review:

- Game.
- Branch.
- Version.
- Release type.
- Changelog.
- Build directory.

Confirm the operation only when all values are correct.

Launcher Forge then:

1. Scans the files.
2. Calculates SHA-256 hashes.
3. Generates the build manifest.
4. Detects the files that must be uploaded.
5. Uploads the required artifacts.
6. Creates the new version.

## If the upload fails

The CLI should display the cause and return you to a usable menu instead of closing unexpectedly.

Common causes include:

- Invalid or expired session.
- Missing game or branch permission.
- Duplicate version.
- Invalid packaged folder.
- Storage limit reached.
- Network interruption.
- Missing executable.
- The selected files changed during the upload.

Correct the reported cause before retrying.
