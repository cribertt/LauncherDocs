# Publicar tu primera build

Launcher Forge publica las builds mediante una **CLI interactiva**.

No necesitas escribir un comando de despliegue ni memorizar parámetros. La CLI te guía durante todo el proceso mediante menús y preguntas.

<Warning>
  Publicar el juego dentro del Catálogo solamente hace visible su ficha dentro del launcher. No sube los archivos del juego. Debes publicar al menos una build mediante la CLI para que los jugadores puedan instalarlo y ejecutarlo.
</Warning>

## Antes de comenzar

Confirma lo siguiente:

- El juego existe dentro del Catálogo.
- Su estado es **Published**.
- Tiene al menos una rama.
- El acceso mediante CLI está habilitado.
- Tienes una build empaquetada que funciona correctamente.
- Tu cuenta tiene permisos para publicar builds.
- El workspace tiene almacenamiento disponible.
- Conoces el ejecutable utilizado para iniciar el juego.

<Note>
  Las cuentas creadas mediante Google o GitHub pueden necesitar establecer una contraseña de Launcher Forge antes de iniciar sesión en la CLI mediante correo y contraseña.
</Note>

## 1. Abre la sección CLI

Inicia sesión en el dashboard de Launcher Forge.

En el menú lateral izquierdo, selecciona **CLI**.

Launcher Forge mostrará los juegos disponibles para publicar.

Selecciona la tarjeta del juego o utiliza **Open CLI**.

  <img
    src="/images/screenshots/cli-dashboard-select-game.png"
    alt="Página CLI de Launcher Forge con la tarjeta del juego y Open CLI destacados"
  />
</Frame>

<Info>
  La CLI solamente obtiene los juegos y permisos disponibles para la cuenta autenticada.
</Info>

## 2. Descarga el ejecutable de la CLI

La página específica del juego muestra:

- Application ID.
- Cantidad de ramas.
- Rama predeterminada.
- Estado del acceso mediante CLI.
- Versión del ejecutable.
- Tamaño de la descarga.

Selecciona **Download CLI**.

<Frame caption="Descarga el ejecutable de Launcher Forge CLI">
  <img
    src="/images/screenshots/cli-game-download.png"
    alt="Página CLI del juego con el botón Download CLI destacado"
  />
</Frame>

El archivo descargado es un ejecutable de Windows listo para utilizar.

No necesitas instalarlo.

Puedes:

1. Guardarlo en el escritorio o en otra carpeta.
2. Hacer doble clic en el ejecutable.
3. Comenzar a utilizar la CLI inmediatamente.

<Warning>
  Descarga la CLI solamente desde el dashboard oficial de Launcher Forge. No ejecutes copias recibidas desde fuentes desconocidas.
</Warning>

## 3. Inicia sesión

Cuando no exista una sesión activa, la CLI mostrará:

```text
No hay una sesión activa. Inicia sesión para continuar.
```

Ingresa el correo electrónico asociado a tu cuenta de desarrollador de Launcher Forge.

Luego la CLI solicitará tu contraseña.

<Frame caption="Inicia sesión con tu correo y contraseña de Launcher Forge">
  <img
    src="/images/screenshots/cli-login.png"
    alt="Launcher Forge CLI solicitando el correo de la cuenta de desarrollador"
  />
</Frame>

<Note>
  Iniciar sesión en el dashboard no inicia automáticamente una sesión dentro de la CLI. La CLI mantiene su propia sesión local.
</Note>

Después de iniciar sesión correctamente, la CLI muestra:

- Correo de la cuenta.
- Plan activo.
- Estado de la cuenta.
- Uso de almacenamiento.
- Uso de ancho de banda.
- Cantidad de juegos permitidos y creados.

## 4. Selecciona Upload build

El menú principal muestra las acciones disponibles.

Selecciona **Upload build**.

<Frame caption="Selecciona Upload build desde el menú interactivo">
  <img
    src="/images/screenshots/cli-main-menu.png"
    alt="Menú principal de Launcher Forge CLI con Upload build seleccionado"
  />
</Frame>

El menú también puede incluir:

- Account / usage.
- List games.
- List versions.
- Version info.
- Logout.
- Exit.

## 5. Selecciona el juego

La CLI carga los juegos disponibles para tu cuenta.

Selecciona el juego al que deseas subir la build.

El juego se muestra junto a su Application ID.

<Frame caption="Selecciona el juego que recibirá la build">
  <img
    src="/images/screenshots/cli-select-game.png"
    alt="Selección del juego en Launcher Forge CLI con su Application ID"
  />
</Frame>

## 6. Selecciona la rama

Después de elegir el juego, la CLI carga sus ramas disponibles.

Selecciona la rama de destino.

<Frame caption="Selecciona la rama de destino">
  <img
    src="/images/screenshots/cli-select-branch.png"
    alt="Selección de rama en Launcher Forge CLI con la rama main disponible"
  />
</Frame>

Algunos ejemplos son:

- `main`
- `stable`
- `beta`
- `development`
- Una rama privada autorizada

<Warning>
  Revisa cuidadosamente la rama seleccionada. Publicar una build de prueba en una rama de producción puede exponerla a jugadores.
</Warning>

## 7. Ingresa la versión y el tipo de publicación

Ingresa un número de versión nuevo.

Se recomienda utilizar versionamiento semántico:

```text
MAJOR.MINOR.PATCH
```

Ejemplos:

```text
1.0.0
1.1.0
1.1.1
```

No reutilices una versión que ya exista para el juego y la rama seleccionados.

Luego la CLI solicitará el tipo de publicación.

<Frame caption="Ingresa la versión y selecciona el tipo de publicación">
  <img
    src="/images/screenshots/cli-release-type.png"
    alt="Launcher Forge CLI solicitando versión y tipo STABLE, PATCH o HOTFIX"
  />
</Frame>

<Tabs>
  <Tab title="STABLE">
    Publica una versión completa nueva del juego.

    Se suben todos los archivos, incluso cuando algunos ya existen.
  </Tab>

  <Tab title="PATCH">
    Publica una actualización planificada con cambios menores.

    Launcher Forge compara el manifiesto y sube los archivos necesarios para la nueva versión.
  </Tab>

  <Tab title="HOTFIX">
    Publica una corrección urgente.

    Utiliza el flujo de comparación del manifiesto, pero identifica la release como una corrección urgente.
  </Tab>
</Tabs>

## 8. Añade las notas y selecciona la carpeta

Ingresa notas opcionales o un changelog.

Escribe una descripción breve y comprensible para los jugadores.

Ejemplo:

```text
Se añadió reasignación de controles, se mejoraron los tiempos de carga y se corrigió un cierre inesperado al cambiar de región.
```

Luego la CLI solicitará la ruta de la carpeta empaquetada.

<Frame caption="Ingresa las notas y la ruta de la build empaquetada">
  <img
    src="/images/screenshots/cli-build-folder.png"
    alt="Launcher Forge CLI solicitando notas y la carpeta de la build"
  />
</Frame>

Selecciona la carpeta raíz que contiene los archivos empaquetados.

Ejemplo:

```text
MiJuegoBuild/
├── MiJuego.exe
├── MiJuego_Data/
├── UnityPlayer.dll
└── Otros archivos de ejecución
```

No selecciones:

- La carpeta del proyecto de Unreal Engine o Unity.
- Código fuente.
- Caché del editor.
- Archivos intermedios.
- Archivos temporales.
- Carpetas con credenciales.

<Warning>
  No muevas, renombres ni modifiques la carpeta seleccionada mientras la CLI la analiza o la sube.
</Warning>

## 9. Confirma el ejecutable principal

Launcher Forge escanea la carpeta y genera el manifiesto.

La CLI informa:

- Cantidad de archivos.
- Cantidad de hashes únicos.
- Ejecutables detectados.

Cuando encuentra uno o más ejecutables, selecciona el ejecutable principal del juego.

Launcher Forge puede marcar una opción como **Recommended**.

<Frame caption="Confirma el ejecutable principal detectado por la CLI">
  <img
    src="/images/screenshots/cli-main-executable.png"
    alt="Launcher Forge CLI mostrando el manifiesto y el ejecutable principal recomendado"
  />
</Frame>

El ejecutable seleccionado es el archivo que Launcher Forge utilizará para iniciar el juego instalado.

<Warning>
  Confirma este valor cuidadosamente. Elegir el ejecutable incorrecto puede permitir la instalación, pero impedir que el juego se inicie.
</Warning>

## 10. Espera la subida

Antes de transferir los archivos, la CLI muestra el modo de publicación y la subida estimada.

En una release `STABLE`, Launcher Forge fuerza la subida completa de la versión empaquetada.

Luego la CLI comienza a subir los archivos y muestra el progreso.

<Frame caption="Espera mientras se suben los archivos del juego">
  <img
    src="/images/screenshots/cli-upload-progress.png"
    alt="Launcher Forge CLI subiendo los archivos de una release STABLE"
  />
</Frame>

Mantén abierta la CLI y una conexión estable hasta que termine la operación.

## 11. Confirma la publicación exitosa

Cuando el proceso termina, la CLI confirma:

- Build creada correctamente.
- Número de versión.
- Tipo de publicación.
- Rama de destino.
- Ejecutable principal.
- Subida exitosa.

<Frame caption="Confirma que la build fue publicada correctamente">
  <img
    src="/images/screenshots/cli-upload-success.png"
    alt="Launcher Forge CLI confirmando una build STABLE publicada correctamente"
  />
</Frame>

Presiona **Enter** para volver al menú principal.

<Check>
  Tu primera build fue publicada correctamente.
</Check>

## ¿Qué ocurre después?

Después de publicar:

- La versión aparece en Launcher Forge.
- La release pertenece a la rama seleccionada.
- El launcher utiliza el ejecutable principal seleccionado.
- Los jugadores pueden descargar o actualizar el juego cuando la release esté disponible para ellos.

Revisa:

- Número de versión.
- Rama.
- Tipo.
- Release notes.
- Ejecutable principal.
- Estado de la build.
- Instalación e inicio desde el launcher.

## Si la subida falla

La CLI muestra la causa y debería devolverte a un menú utilizable en lugar de cerrarse inesperadamente.

Algunas causas frecuentes son:

- Sesión inválida o vencida.
- Permisos insuficientes.
- Versión duplicada.
- Carpeta empaquetada inválida.
- Límite de almacenamiento.
- Interrupción de red.
- Ningún ejecutable detectado.
- Archivos modificados durante la subida.

Corrige la causa informada antes de volver a intentarlo.
